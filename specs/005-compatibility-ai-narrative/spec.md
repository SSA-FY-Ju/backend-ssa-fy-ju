# Feature Specification: 기업 궁합 분석 AI 해설 전환 및 점수 산정 일원화

**Feature Branch**: `005-compatibility-ai-narrative`

**Created**: 2026-08-13

**Status**: Draft

**Input**: User description: "회사 궁합 분석의 텍스트 해설(시너지/경고/전략/면접질문/역할별 사유/월별 조언/주의사항/요약)을 규칙 기반 고정 템플릿에서 AI가 생성하는 서술형 텍스트로 전환한다. 숫자 점수 산정 로직은 그대로 유지하되, 직군 매칭 점수와 역할별(전문가/리드) 궁합 점수가 서로 다른 산식을 쓰던 기존 불일치를 하나의 기준으로 통합한다. 동시 요청 중복 생성 방지(분산락)는 이번 범위 밖이며 specs/004-redis-hardening-refactor의 별도 작업으로 다룬다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 개인화된 궁합 해설 받기 (Priority: P1)

취업 준비생이 기업/직무 궁합 분석을 요청하면, 시너지·경고·실행 전략·예상 면접 질문·역할별 추천 사유·월별 조언·주의사항·한 줄 요약이 고정된 문구가 아니라 자신의 사주 오행과 지원 기업·직군 조합에 맞춰 자연스럽게 서술된 설명으로 제공된다.

**Why this priority**: 현재는 동일한 오행 조합이면 완전히 동일한 문장이 반복 노출되어 서비스의 신뢰도·설득력이 낮다. 서술형 해설은 사용자가 직접 체감하는 핵심 가치이며 이 기능의 존재 이유다.

**Independent Test**: 서로 다른 사용자 오행/기업/직군 조합으로 궁합 분석을 5회 이상 요청했을 때, 8개 해설 텍스트 필드가 매번 동일한 문구로 반복되지 않고 입력 조합을 반영한 서로 다른 문장으로 나오는지 확인한다. 점수 계산 로직 변경 없이도 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 처음 보는 기업/직군 조합으로 궁합 분석을 요청, **When** 분석이 완료됨, **Then** 응답의 해설 텍스트 8개 필드 모두 해당 사용자의 오행/직군 정보를 반영한 서술형 문장으로 채워진다.
2. **Given** 동일한 사용자가 같은 달에 같은 기업/직군으로 재요청, **When** 캐시된 결과가 있음, **Then** 이전에 생성된 해설 텍스트가 그대로 재사용되고 새로 생성되지 않는다(기존 월별 캐시 정책 유지).

---

### User Story 2 - 일관된 점수 체계로 신뢰도 확보 (Priority: P2)

사용자가 궁합 분석 결과에서 "직군 자체와의 매칭 점수"와 "그 직군 내 세부 역할(전문가/리드)별 점수"를 함께 볼 때, 두 점수가 같은 사주 오행 데이터에서 나온 결과임에도 서로 다른 산정 기준으로 계산되어 앞뒤가 안 맞는 인상을 주지 않는다.

**Why this priority**: 텍스트 해설과 별개로 존재하던 기존 결함으로, 사용자가 숫자를 근거로 신뢰 판단을 내리는 궁합 분석의 핵심 지표에 영향을 준다. 텍스트 전환과 함께 정리하는 것이 효율적이라고 판단되어 이번 범위에 포함한다.

**Independent Test**: 동일한 사용자 오행 분포를 다양한 값으로 대입했을 때, 직군 매칭 점수와 역할별(전문가) 점수가 하나의 통일된 계산 기준에서 파생된 값인지(같은 입력 → 일관된 상대적 관계)를 수동 계산값과 대조하여 확인한다. AI 텍스트 생성과 무관하게 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자의 주 오행 보유 개수가 동일한 두 가지 분석 요청, **When** 각각 직군 매칭 점수와 역할별 점수를 계산, **Then** 두 점수 체계가 동일한 산정 기준(가중치)에서 파생되어 서로 모순되는 값(예: 매칭 점수는 낮은데 역할 점수는 매우 높음)이 나오지 않는다.

---

### User Story 3 - AI 서비스 장애 시에도 안전하게 실패 처리 (Priority: P3)

AI 해설 생성이 실패(타임아웃, 서비스 오류 등)하더라도 사용자의 일일 분석 가능 횟수가 소진된 채로 남지 않으며, 사용자는 원인을 알 수 있는 명확한 오류 안내를 받는다.

**Why this priority**: 기존 커리어 컨설팅·궁합 분석 기능에 이미 적용된 "쿼터 보상" 원칙과의 일관성을 지키기 위함이며, 신뢰성 측면에서 중요하지만 핵심 가치(User Story 1)보다는 우선순위가 낮다.

**Independent Test**: AI 해설 생성 호출이 실패하는 상황을 재현했을 때, 사용자의 일일 사용 횟수가 요청 전과 동일하게 유지되고 응답이 부분적으로 깨진 형태가 아닌 명확한 오류로 반환되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** AI 해설 생성 서비스가 일시적으로 응답하지 않음, **When** 재시도 후에도 최종 실패, **Then** 사용자의 일일 분석 가능 횟수는 요청 전과 동일하게 유지되고, 사용자는 원인이 명확한 오류 메시지를 받는다.
2. **Given** AI 해설 생성이 성공했으나 점수 계산 등 이후 단계에서 실패, **When** 최종 저장까지 실패, **Then** 사용자의 일일 분석 가능 횟수는 요청 전과 동일하게 유지된다.

### Edge Cases

- AI가 생성한 해설 텍스트가 비어 있거나 필수 항목 일부가 누락된 형태로 반환되면 어떻게 처리하는가? (기존 커리어 컨설팅 기능의 응답 검증 정책과 동일하게 처리)
- 동일한 사용자가 서로 다른 기업/직군으로 짧은 시간 내 여러 건을 연속 요청할 때, 매 건마다 AI 해설이 개별적으로 생성되는가?
- 점수 산정 기준 통합으로 인해 과거 저장된 궁합 분석 결과(기존 산식으로 계산된 값)와 신규 요청 결과 간 점수 체계가 달라지는 것을 사용자가 인지할 수 있는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 기업 궁합 분석 응답의 해설 텍스트 8개 필드(직군 시너지, 직군 경고, 오행 시너지 설명, 약점 방어 전략, 예상 면접 질문, 역할별 추천 사유, 월별 운세 조언, 주의사항)를 고정 템플릿이 아닌, 해당 요청의 사주 오행·기업·직군 조합을 반영해 생성된 서술형 텍스트로 제공해야 한다.
- **FR-002**: 시스템은 궁합 점수(전체 궁합 점수, 직군 매칭 점수, 역할별 점수, 월별 운세 점수 등)의 산정 로직을 AI 해설 생성 여부와 무관하게 결정론적(규칙 기반) 방식으로 유지해야 한다.
- **FR-003**: 시스템은 "직군 매칭 점수"와 "역할별(전문가/리드) 궁합 점수" 산정에 동일한 계산 기준을 적용하여, 같은 사용자 오행 입력에 대해 두 점수 체계가 서로 모순되지 않도록 해야 한다.
- **FR-004**: 시스템은 AI 해설 생성이 실패한 경우, 이미 차감된 사용자의 일일 분석 가능 횟수를 요청 이전 상태로 복원해야 한다.
- **FR-005**: 시스템은 AI 해설 생성 실패 시 사용자에게 원인을 알 수 있는 명확한 오류를 반환해야 하며, 일부 필드만 채워진 불완전한 응답을 반환해서는 안 된다.
- **FR-006**: 시스템은 동일한 사용자가 같은 달에 동일한 (기업, 직군) 조합으로 재요청할 경우, 기존에 저장된 AI 해설 텍스트를 재사용하고 AI를 재호출하지 않아야 한다(기존 월별 캐시 정책 유지).
- **FR-007**: 궁합 분석 응답의 필드 구조(필드명·형식)는 이번 변경으로 인해 달라지지 않아야 하며, 값의 내용(텍스트 문구, 점수 수치)만 변경 대상이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 서로 다른 입력 조합으로 수집한 궁합 분석 응답 표본 중, 8개 해설 텍스트 필드가 동일한 문구로 반복되는 비율이 5% 미만이다.
- **SC-002**: 동일한 사용자 오행 입력에 대해 산출된 직군 매칭 점수와 역할별(전문가) 점수가 100% 동일한 계산 기준에서 파생된다(별도 산식으로 인한 괴리 0건).
- **SC-003**: AI 해설 생성 실패가 발생한 요청 중, 사용자의 일일 분석 가능 횟수가 소진된 채로 남는 비율이 0%다.
- **SC-004**: 사용자는 궁합 분석 결과를 15초 이내에 받아볼 수 있다.
- **SC-005**: 기존 프론트엔드가 소비하는 응답 필드 구조에 대한 하위 호환이 100% 유지된다(필드 추가/삭제/이름 변경 없음).

## Assumptions

- 기존 규칙 기반 점수 산정 로직(오행/십신 비교, 관성 조화 등)은 그대로 유지하며, 이번 기능은 해설 텍스트 생성 방식과 두 점수 체계 간 산정 기준 통합에만 관여한다.
- AI 해설 생성에 사용할 외부 AI 서비스는 기존 커리어 컨설팅 기능에서 이미 사용 중인 서비스와 동일한 수준의 가용성·응답 형식 신뢰도를 가진다고 가정한다.
- 쿼터 차감/복원 정책은 기존 커리어 컨설팅·궁합 분석 기능에 이미 적용된 보상 트랜잭션 방식을 그대로 재사용한다.
- 동시 요청에 대한 중복 생성 방지(분산락)는 `specs/004-redis-hardening-refactor`의 별도 계획(User Story 5)에서 다루며, 이번 기능 범위에서 제외한다. 두 작업이 합류할 때는 락 유지 시간(lease time)이 AI 해설 생성 호출 지연을 충분히 수용하는지만 별도로 재검토한다.
- 응답 JSON의 필드 구조는 변경하지 않으며, 텍스트 문구와 점수 수치(값)만 변경 대상이다. 프론트엔드가 특정 값을 하드코딩해 검증하고 있다면 별도 조정이 필요할 수 있다.
